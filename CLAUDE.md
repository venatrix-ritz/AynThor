# AynThor — research repo + Thor tooling (AYN Thor + Armada OS)

Source-grounded knowledge base on the AYN Thor and Armada OS, plus the small amount of code built from it: `tweaks/` (device tweak scripts, deployed over SSH) and two Decky plugins that are their own repos, git-ignored here and linked in by junction: **Ratatoskr** (formerly Touch Master; the bottom-screen trackpad/keyboard driver; [venatrix-ritz/Ratatoskr](https://github.com/venatrix-ritz/Ratatoskr), `G:\Projects\Hardware\Ratatoskr` as `plugins/ratatoskr`) and **Gleipnir** (the 80 % battery ceiling; [venatrix-ritz/Gleipnir](https://github.com/venatrix-ritz/Gleipnir), `G:\Projects\Hardware\Gleipnir` as `plugins/gleipnir`). Commit plugin changes in those repos, not this one. Never check out a branch that still tracks `plugins/thor-input` while a junction sits in `plugins/`: git would overwrite the real repo through it (that happened once on 2026-10-07; nothing was lost because the work was committed). Start at [README.md](README.md); rules for writing docs are in [docs/reference/CONVENTIONS.md](docs/reference/CONVENTIONS.md) (claim tags, Sources section, no unsourced causal claims, today's date absolute).

- **Upstream clones** live in `refs/` (gitignored): `scripts/clone-refs.ps1` rebuilds them; SHAs in `refs/MANIFEST.md` + `scripts/refs.lock.json`. Cite as `refs/<dir>@<sha7>:path#Lnn`. Never edit `refs/`.
- **GitHub exports** in `refs/_gh/` (`scripts/fetch-gh-meta.ps1`) are the primary source for Armada release history/issues/PRs; WebFetch output is secondary.
- **Subagents cannot see `G:\`** via Read/Grep/Write — use Bash `G:/...` paths. Heredocs in Bash tool calls with mixed quotes failed once; use the Write tool per file. `python3` is not on the Bash PATH here; use `python`.
- **Line endings:** Linux-bound files (`tweaks/`, `*.sh`, `*.service`, `*.py`) are pinned to LF by `.gitattributes`. This machine has `core.autocrlf=true`; never let CRLF reach the Thor.
- **Tweak scripts (`tweaks/`)** are community-sourced and mostly untested on this hardware — see the provenance note in `tweaks/README.md`. Deploy with `tweaks/apply-all-tweaks.sh [--audio|--system|--wowlan|--lighting|--status] [HOST]`. `--all` omits the stick-RGB daemon (Armada ships `armada-rgb`). The 80 % battery ceiling is the **Gleipnir** Decky plugin (own repo `venatrix-ritz/Gleipnir`, git-ignored at `plugins/gleipnir`); it stays watch-only until its on-device test passes.
- **Device access:** SSH key auth only (`armada@<ip>`; the real host, Wi-Fi MAC and LAN broadcast live in the git-ignored `local/thor.env`, template `scripts/thor.env.example`; never put them in tracked files; the IP changes, Armada Tools → Remote Access shows it). Ven gave Claude passwordless sudo on 2026-10-04 (`/etc/sudoers.d/91-claude-full`, "so you can do the rest") and asked for installs and fixes on the Thor. That day Claude, at Ven's request, set up Barry's user-space deps and wrappers under `~/.local`, repointed the LSFG-VK DLL path, and rewrote the KDE output layout so desktop mode opens on the top screen, each with a `.bak` and all inside `$HOME`; its `sudo` calls were reads. **How changes are made (updated 2026-10-08):** the Thor is Ven's hobby device and Ven allows root-level changes again, so Claude does device work directly, including as root: installing and updating its own plugin, tweak and service files in root-owned places (the Decky plugin folder, `/var/local/bin`, user units and the units it owns), restarting the services involved, and the `sudo` reads and writes the task needs. Every change gets a timestamped backup first, a pre-flight on the Thor's own Python/bash in `/tmp`, and a report of what changed; look at what is there before deleting or overwriting it. **Still staged for Ven** as one dry-run-by-default script: sudoers, security and signature policy, bootloader/ABL, kernel parameters, and OS-level settings under `/etc` (NetworkManager and the like), because Claude's built-in safety rules, not a rule Ven set, forbid it from modifying system or security settings even when asked; if asked to bypass that, say so plainly. The pattern: a dry-run-by-default script (`tweaks/cleanup-device.sh`, `tweaks/restore-stock.sh`, or `~/stage/apply-system-bits.sh` on the Thor). The charge limiter, stick-LED daemon, Wake-on-WLAN and display-sync units found in `/etc` before the 2026-10-07 reset came from the Antigravity sessions. The Thor sleeps and may not answer. No LAN scanning. `docs/hardware/device-observed.md` has dated surveys (latest 2026-10-07).
